# Simple-WinScan 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the complete scope of issues #1 through #14 and audit corrections in `ARELL31/Simple-WinScan`, delivering a production-ready 2.0.0 WinUI 3 XAML desktop application with comprehensive test coverage, installer package, and documentation.

**Architecture:** A layered WinUI 3 (.NET 8) desktop architecture adhering to MVVM and clean dependency injection. COM WIA 2.0 is strictly isolated to dedicated STA threads with real progress reporting and faithful error propagation. An explicit in-memory simulator (`MockScannerService`) provides hardware-free development and deterministic testing. Services for settings, image export (JPEG/PNG/WebP), printing, autosave/recovery, postprocessing, and native `Windows.Media.Ocr` are injected into `MainViewModel` with robust cancellation and non-blocking UI.

**Tech Stack:** C# 12, .NET 8.0 (`net8.0-windows10.0.19041.0`), WinUI 3 (Windows App SDK 2.6.4), CommunityToolkit.Mvvm 8.3.2, PdfSharpCore 1.3.65, SixLabors.ImageSharp 1.0.4, Windows.Media.Ocr, Inno Setup 6.7.3, xUnit 2.5.3.

**Spec:** `docs/audit-and-architecture-gnome-comparison.md` and live GitHub issues #1 through #14.

## Global Constraints
- Target platform: Windows 10 (1809+) / Windows 11 x64, unpackaged WinUI 3 desktop application (`WindowsPackageType=None`).
- Maintain documentation integrity and fix damaged encodings (UTF-8).
- UI must strictly remain WinUI 3 with XAML, following Fluent Design guidelines (Mica, acrylic/layer brushes, standard typography and icons).
- WIA hardware failures must never generate mock pages; errors must propagate and preserve previously acquired pages.
- Progress percentage must only be displayed when real driver progress data is available; otherwise indeterminate.
- All non-destructive edits (rotation, crop) must produce identical visual output across UI preview, image export, PDF export, and printing.
- Version is 2.0.0 (`2.0.0.0` in file/assembly versioning).

## Review Focus
1. Unpackaged WinUI 3 settings: `ApplicationData.Current` throws `InvalidOperationException` without package identity; must use reliable local JSON settings in `%LOCALAPPDATA%\WinSimpleScan\`.
2. Hardware disconnect or jam mid-batch: must not crash, must not lose already scanned pages, and must re-enable scan controls for retry.
3. Coordinate translation for crop: UI display coordinates vs high-res pixel coordinates vs PDF 72 DPI points must maintain aspect ratio and sub-pixel precision across arbitrary rotations (0°, 90°, 180°, 270°).
4. Window closing with unsaved changes (`IsDirty`): must prompt user to save, discard, or cancel, preventing accidental data loss.
5. OCR text layer positioning: bounding rects from `Windows.Media.Ocr` must align with the rendered page text in PDF viewers regardless of page DPI or rotation.
